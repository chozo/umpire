# 球審ジャッジ

プレイヤーは野球の球審。キャッチャーの後ろから3Dの投球を見て、**ストライクかボールか**をコールするブラウザ用ミニゲームです（縦型 9:16、スマホ・PC対応）。

## 遊び方

- ピッチャーが投げた球がミットに収まってから **1.5秒以内** に「ボール」か「ストライク」を押す
  - PC: <kbd>F</kbd>（または ←）= ボール、<kbd>J</kbd>（または →）= ストライク
  - ボールが本塁の手前に来る前の入力は「まだ早い！」として無視する
- **誤審（時間切れを含む）が3回で退場**するまで、球数の上限なしで続く。段階が変わる球では画面下に予告を出す
  - 第1〜3球: 練習（チュートリアル）。際どい球は出さず、ストレートとカーブだけを変化を小さく（0.6倍）して投げる。ストライクはベースに12cm以上かかり、ボールはベースから15cm以上外れる。第2球は第1球と逆（ストライクとボールの両方を見せる）
  - 第11球から: サイドスロー・アンダースローの投手が出る
  - 第21球から: 投手がプレートの端に立って投げ、投球に角度がつく
  - 第31球から: 5球ごとに球速が5%ずつ上がる（第31〜35球は+5%、第36〜40球は+10.25%、…）
- 際どい球（ボールの端とベースの端の差が3cm未満）と誤審のときは、リプレイで判定を検証する
  1. 球審の視点で、スロー再生と軌跡を表示
  2. 真上から見た図で、ボールの通り道（ボールの幅の帯）とベースとの距離（cm）を表示
  - リプレイはどの時点でもタップ（PCは Space / Enter / F / J）でスキップできる（開始直後0.3秒は押し間違い防止のため無視）

## 判定のルール

- **ボールの一部でも、ホームベース（五角形）の真上を、前端から後ろの頂点までのどこかで通過すればストライク**
- 高さは判定しない（真上から見た左右と前後の位置だけ）
- ボールの直径は 7.3cm、ベースの幅は 43.2cm（実寸）
- 判定は軌道を細かく区切り、ボールの中心とベースの五角形との符号付き距離が最小になる点で行う（`src/pitch.ts` の `judge`）
- 画面の投球と判定は同じ軌道データから作っている

## 投球

| 球種 | 球速（ストレート比） | 変化（右投手） |
|---|---|---|
| ストレート | 100% | ホップ気味、わずかにシュート方向 |
| カーブ | 78% | 大きく落ちながら一塁側へ |
| スライダー | 87% | 一塁側へ大きく |
| スイーパー | 83% | 一塁側へとても大きく（横の変化が最大） |
| カットボール | 95% | 一塁側へ小さく |
| シュート | 92% | 三塁側へ大きく |
| シンカー | 90% | 沈みながら三塁側へ大きく |
| ツーシーム | 97% | 三塁側へ |
| チェンジアップ | 82% | 沈みながら三塁側へ |
| フォーク | 87% | 縦に落ちる |

- 見て分かるよう、変化は実際の投球より大きめにしている（横の変化の加速度は 10m/s² が上限）
- 左投手は左右が逆になる
- 投げ方: オーバー（スリークォーター）、サイドスロー、アンダースロー。サイドとアンダーは低く横から投げるので斜めに入ってくる角度がつき、横の変化が1.2〜1.3倍になる（アンダーは浮き上がる）
- **角をかすめる球**: 斜めに横切る球は、ベースの前の角だけ（外へ逃げる球）や、奥だけ（内へ入ってくる球）にかかる。ミットに収まる位置はベース上を通った位置から横にずれるので、ミットの位置だけを見ていると間違える。リプレイの説明では「ベースの前の角に」「ベースの奥から」のように場所も示す
- 軌道は「重力＋回転による変化（一定の加速度）＋空気抵抗による減速」で計算する。通過させたい位置から初速を逆算し、ストライク・ボール・際どい球の割合を調整する
- 難易度は投球が進むにつれて上がる（`src/config.ts` の `difficulty`）。第15球までで一通りそろい、第16〜40球でさらに上がる
  - ストレートの球速: 132km/h →（第15球）156km/h →（第30球）159km/h。第31球からは5球ごとに5%ずつ上がり、第31球168km/h、第41球188km/h、第51球207km/h
  - 変化の大きさ: 1.0倍 → 1.15倍 → 1.5倍
  - 際どい球（3cm未満）の割合: 30% → 60% → 75%。そのうち前の角・奥を狙う球: 35% → 60% → 85%
  - 球種: 第1〜3球はストレート・スライダー・カーブ → シュート → カット・ツーシーム・フォーク → チェンジアップ・スイーパー・シンカー。第16球からは変化球（特にスライダー・シュート・スイーパー・シンカー）が多くなる
  - 左投手: 第6球から40%
  - サイドスロー: 第11球から25%→30%、アンダースロー: 第11球から12%→25%
  - プレートの端: 第21球から75%の球で、プレート（幅61cm）の一塁側か三塁側の端に立つ（体の中心が中央から24cm横）。リリース位置も同じだけ横にずれ、斜めに入ってくる。捕球後の球種表示に「プレートの三塁側から」のように出す

## 見た目

- ピッチャーは箱や円柱を組み合わせたローポリの人形（外部素材なし）で、投球フォームはキーフレームをなめらかに補間して動かす（`src/pitcher.ts`）。18m先でもフォームが見えるよう、実寸の1.15倍で描いている
- ボールはピッチャーの手の位置（リリースの姿勢から計算）から投げられる
- カメラはキャッチャーの真後ろ（x = 0）に置いている。そのため、ボールとベースの左右の位置関係は遠近のずれなく見える
- 構えから足を上げるまではピッチャーを大きく映し、リリースの前に球審の視点まで引く
- キャッチャーは体の近く（ベースの後ろの頂点から95cm）で捕り、手を前に出さない。ミットは、ボールがベースを通り過ぎるまで低く構えたまま（`MITT_LOW_Y`）横にだけ寄せ、通過後に捕球位置へ上げ、捕球後はボールごと低い位置へ下ろす。そのため、ボールがベースの上を通る間と判定を考える間は、ミットがベースに重ならない（400球で計算: 通過までの重なり0球、下ろした後0球。捕球の瞬間だけ約9%が一瞬重なる）
- カメラは見下ろし27°・画角63°。体の近くで捕るミットとボールが、ベースの下側に映る
- ボールの高さは判定に関係しないので、捕球位置がベースより下に映るよう低め（ベース上で40〜100cm）に投げる

## 音

- 効果音（捕球音・風切り音・正解・誤審・退場）と BGM は、すべて Web Audio で合成している（外部の音源ファイルなし）
- BGM は応援風の自作曲（トランペット・太鼓・メガホン・観客のざわめき。後半は三三七拍子）。150BPM・8小節（12.8秒）を最初に一度だけ合成してループ再生する
- リプレイ中は BGM の再生速度を 0.7倍に落とし、高い音を削る（テープの遅回しのように少し低くこもる）。リプレイが終わると元に戻る
- 試合開始で流れ、退場・タイトルへ戻ると止まる。タブを隠すと音を止める
- タイトル画面・結果画面のボタンか <kbd>M</kbd> キーで BGM をオン・オフできる（ブラウザに保存）

## スコア

- 正解: 100点（際どい球は300点）＋早押しボーナス（捕球から0.3秒以内のコールは20点、0.7秒以内は10点、それより遅いと0点。捕球前のコールは0.3秒以内として扱う）
- 正解の表示の下に「100 ＋ 20（早押しボーナス）」のように内訳を出し、早くコールするほど高得点だと分かるようにしている（ボーナスが0点のときは「100」のように基礎点だけを出す）
- 称号（退場までに正しくコールした球数）: 100球以上「AI球審」、50球以上「神球審」、40球以上「名球審」、30球以上「一軍の球審」、20球以上「二軍の球審」、10球以上「審判見習い」、それ未満「草野球の審判」
- 自己ベストの得点をブラウザ（localStorage）に保存する

## ファビコン・OGP

- ファビコン: `public/favicon.svg`（野球のボール）
- OGP: `public/ogp.png`（1200×630）。際どい球のリプレイ（球審の視点の軌跡と、真上から見た図）とタイトルを並べたもの。`node tools/create-ogp.mjs <開発サーバーのURL>` で作り直せる

## 告知動画

- `npm run promo` で、ビルドしてから告知動画（縦型 1080×1920・30fps・約31秒）を撮って書き出す。出力はアプリの隣の `../video/`（`umpire-promo.mp4`、表紙 `umpire-promo-cover.jpg`、確認用の一覧 `umpire-promo-sheet.jpg`）。動画はリポジトリに含めない
- 台本は `tools/promo/scenario.js`、見た目は `tools/promo/promo.css`。狙った投球は `__game.repitch(...)` と `__game.setIndex(n)` で作る
- `PROMO_EVERY=15 npm run promo` で15コマおきの一覧画像だけを作って構成を確認できる。`PROMO_ENCODE_ONLY=1 npm run promo` で撮り直さずに書き出しだけやり直す
- 音はゲームの効果音と応援曲そのもの（`__game.audio.render` で書き出し用に鳴らし直す）。リプレイ中の BGM のスローも同じように入る。音量は -14 LUFS

## 構成

```text
index.html
public/favicon.svg
src/
  config.ts    調整値（カメラ・判定のしきい値・時間・得点・難易度）
  pitch.ts     軌道の計算・判定・投球の生成（DOMに依存しない）
  pitcher.ts   ピッチャーの人形と投球フォーム
  scene.ts     球場・キャッチャーとミット・ボール・リプレイ表示・カメラ
  audio.ts     Web Audio で合成した効果音（捕球音・風切り音・正解・誤審）と応援風の BGM
  main.ts      ゲームの進行・UI・確認用の入口 window.__game
  style.css
tests/pitch.test.ts   判定と投球生成の単体テスト（vitest）
tools/e2e.mjs         ブラウザでの通し確認（playwright-core + インストール済みChrome）
tools/create-ogp.mjs  OGP画像 public/ogp.png を作る
tools/promo/          告知動画の撮影と台本
tools/dev/            開発用の撮影スクリプト（フォームの確認など）
```

## 開発

```sh
npm install
npm run dev        # http://localhost:5173/
npm test           # 単体テスト
npm run build      # 型チェック + dist/umpire/ に出力
npm run e2e -- http://localhost:5173/   # 開発サーバーを起動した状態で
npm run deploy     # ビルドして Cloudflare Workers へ公開
```

- `?seed=数値` を付けると投球の並びを固定できる
- `window.__game` で状態の取得（`state()`）、コール（`call('strike')`）、時間の速さの変更（`setTimeScale`）、次の投球の指定（`repitch({ type, lefty, slot, rubberX, category, margin, side, clip })`）、1コマずつ進める操作（`manual(true)` と `step(dt, n)`）ができる

## 確認済みのこと（2026-10-16）

- 単体テスト 16件: ベースとの距離、目標点の通過、境界（ボール半径ちょうど）、ベースの後ろの角だけをかすめる変化球、投球生成のカテゴリと余白の精度、「全部ストライク」「全部ボール」では正解率が6割に届かないこと
- 単体テスト（追加）: 前の角・奥だけをかすめる球を指定して作れること、サイドスロー・アンダースローは第11球から出ること、第21球からプレートの端から投げること、第31球から5球ごとに5%速くなること、第1〜3球は際どい球がないこと
- e2e（ヘッドレスChrome、405×720・360×640・1280×720）: 最初の3球が際どくなくストライクとボールの両方が出ること、15球を超えて続くこと、第11・21・31球の予告と各段階の登場時期（第32球まで通しプレイ）、変則投手・球種・角をかすめる球が出ること、誤審3回で終了、称号と自己ベスト、もう一度、2試合目でも判定が表示されること、早すぎる入力、時間切れ、タイトルへ戻る、左投手の際どい球とリプレイの説明、サイドスローのスイーパーが前の角をかすめるリプレイ、リプレイの途中スキップ、BGM（試合中に流れる・リプレイ中はスロー・退場で止まる・オン/オフ）、PCでの9:16表示、コンソールエラーなし
- 本番ビルド（`vite preview`）でも e2e が成功
